# 2. Quy ước REST API chung

- Base URL local: http://localhost:8080; public API đi qua API Gateway.
- Protected API dùng Authorization: Bearer \<accessToken\>; public API khai báo security: []. Internal worker endpoints dùng service authentication riêng theo cấu hình triển khai.
- Mỗi operation khai báo x-owner-service, x-required-permissions hoặc x-any-of-permissions, x-data-scope; x-idempotency-required cho operation cần chống lặp.
- HTTP 200 + data: \[\] + meta.totalElements: 0 dùng cho danh sách rỗng; không dùng 404 chỉ vì danh sách không có phần tử.
- 400: sai cú pháp/path/query; 422: validation hoặc business rule; 401: token; 403: thiếu permission/scope; 404: resource không tồn tại/không được tiết lộ; 409: conflict, hết slot, idempotency conflict hoặc state transition sai; 429: rate limit; 500/503: lỗi service/dependency.
- DELETE thành công trả 204 No Content. Các response dùng camelCase; persistence columns dùng snake_case.
- Idempotency-Key là HTTP header khai báo qua components.parameters.IdempotencyKey; cùng principal + operation + key + payload trả lại kết quả trước đó; payload khác với cùng key trả 409.
- Không trả reservationTokenHash. Reservation token raw chỉ trả một lần ở response tạo reservation nếu flow convert cần token; hash chỉ lưu nội bộ.

# 4. Luồng nghiệp vụ (WF01–WF12)

| **WF** | **Tên luồng** | **Mô tả** |
|--------|---------------|-----------|
| WF01 | Đăng ký tài khoản | Khách tạo tài khoản → Identity tạo user PATIENT → Consumer tạo patient profile bằng saga/outbox |
| WF02 | Đăng nhập | Identity cấp token → Client dùng token cho các API protected |
| WF03 | Đặt lịch khám online | Patient chọn chuyên khoa/bác sĩ/ngày/slot → Scheduling tạo reservation → Convert → Appointment |
| WF04 | Check-in bệnh nhân | Receptionist xác minh appointment → Tạo Queue Ticket → Cấp số → Trạng thái WAITING |
| WF05 | Gọi bệnh nhân tiếp theo | System/dispatch chọn ticket theo priority_score DESC, checked_in_at ASC, ticket_number ASC |
| WF06 | Bắt đầu lượt khám | Doctor xác nhận bắt đầu khám → QueueTicket → Trạng thái IN_PROGRESS |
| WF07 | Hoàn tất lượt khám | Doctor xác nhận kết thúc khám → QueueTicket → Trạng thái COMPLETED/EXPIRED |
| WF08 | Công bố kết quả khám | Doctor publish encounter → Clinical công bố hồ sơ → Patient xem kết quả qua API/SSE |
| WF09 | Nhắc hẹn lịch khám | Reminder gửi thông báo T-24h, T-2h cho patient |
| WF10 | Đồng bộ realtime | SSE reconnect → Bắt buộc tải REST snapshot |

# 5. BR rules (Business Rules)

| **BR** | **Quy tắc** |
|--------|-------------|
| BR01 | Idempotency: cùng principal + operation + key + payload trả lại kết quả cũ; payload khác trả 409 |
| BR02 | Queue ordering: priority_score DESC, checked_in_at ASC, ticket_number ASC |
| BR03 | Grace period: 15 phút sau giờ hẹn → chuyển status EXPIRED, tạo ticket WALK_IN nếu có |
| BR04 | Data scope: Patient=SELF, Doctor=ASSIGNED, Receptionist=BRANCH, Admin=GLOBAL (có permission) |
| BR05 | Encounter publish: Bệnh nhân chỉ xem chẩn đoán/đơn thuốc sau khi Clinical publish |
| BR06 | Outbox: Write aggregate mutation và outbox_events row cùng transaction; Claim với FOR UPDATE SKIP LOCKED |
